# Stage 5 Calendar activity

The `RealCalendarService` adapter owns `EKEventStore`, full-access authorization, calendar selection, event projection, and change notifications. It exposes value snapshots through `CalendarService`; EventKit objects never reach SwiftUI. `CalendarActivityModel` observes those snapshots and feeds `CalendarReminderCoordinator`, which schedules transient reminders through the shared `ActivityCoordinator`. The shell receives Calendar views through `NotchCalendarRendering`, parallel to the media renderer. Music and Calendar views remain mounted across page switches; Player and Up Next stay within Music.

Calendar access is requested once at app startup through `requestFullAccessToEvents`. The app declares `NSCalendarsFullAccessUsageDescription` and the Calendar sandbox entitlement in both distribution profiles. Denial or restriction leaves Calendar empty and shows a System Settings button and the path to Privacy & Security → Calendars. Returning to Notchium refreshes authorization.

The initial selection includes calendars already configured in macOS Calendar. Identifiers are saved in UserDefaults when the user changes a selection. EventKit queries only selected calendars for the next 14 days and projects the next six non-cancelled events, including an active event. The expanded view shows the next event and up to four following events. No event content is persisted.

Calendar reminders appear at 60, 30, and 5 minutes before a timed event. A meeting can also show Join Now at its start. Each threshold is recorded once per event within the running app. On launch or wake after a threshold, the coordinator presents one reminder using the actual time remaining and marks older thresholds consumed. The soonest event wins; a higher-priority system activity suppresses a stale reminder rather than queuing it. Each banner lasts about ten seconds, with the countdown paused while the pointer is over it. The reminder has priority over collapsed media; dismissing it restores the existing media activity without restarting playback. EventKit is queried at launch, on database changes, day changes, wake, foreground activation, selection changes, and event approach/start/Now/end boundaries. The reminder coordinator uses one scheduled timer for the next threshold, and SwiftUI's one-second `TimelineView` updates only the expanded Calendar countdown.

The collapsed shell widens symmetrically for reminders by up to 64 points beyond the media row (normally 356 points, bounded to 340–380 points without ever narrowing below the hardware/media footprint). Width does not depend on title length. The banner measures its intrinsic height at that fixed target width: a one-line title uses 44 points, two lines use 60, and an optional Join row adds 36. Titles retain their 13-point medium-weight font, wrap to at most two lines, and only then truncate; the countdown stays at the top-right. Horizontal/vertical padding is 20/14 points. The dismiss target reserves space so hovering cannot reflow text. Join occupies its own full-width, centered action row with a compact 26-point capsule and a 10-point gap below the title. Optional location appears last in quieter text; it centers beneath Join for meetings and aligns with the title otherwise. Missing actions/details create no empty rows. The calendar dot is a restrained 5 points, and the countdown uses slightly softer contrast. The Calendar page retains its original 28-point Join style. It uses the same `ExpandedTopSurface` path, black fill, and mask throughout; there is no independently sized reminder outline. A zero-spacing vertical stack places reminder content directly after the unchanged top row. Without music, the same reminder sizing applies with an empty top row. A reversible, bounce-free 320 ms reveal widens first and then grows downward; content fades in over the final 100 ms. Dismissal fades content over 80 ms and reverses the shell reveal. Reduce Motion uses a short 120 ms transition. The existing transparent NSPanel hosts the growing SwiftUI surface; no reminder window is created. Hit testing uses the same bounded reminder width and measured content height. The collapsed artwork follows the media surface independently of the selected expanded page. Clicking the event summary opens the Calendar page; a hovering X dismisses it. Whenever a validated meeting URL exists, Join uses an opaque white (#FFFFFF) capsule with black (#000000) text and video icon at rest, with subtle hover/press scaling. The Calendar page's Join uses the same style. Without a meeting URL, Join is absent. Joining opens the validated URL through `NSWorkspace` and dismisses the reminder.

Join appears only for HTTPS meeting URLs on recognized Zoom, Google Meet, or Microsoft Teams hosts with meeting-shaped paths. Detection checks `EKEvent.url`, then location, then notes. Join delegates to `NSWorkspace`.

Validation: the package test suite includes focused reminder timing, priority, wake, media restoration, and silhouette checks, plus native SwiftUI renders at 1×/2× scale for one-line, two-line, and truncated titles. Hosted renders verify measured height reaches the shell and hit target, with and without music/Join. Pixel checks verify Join and Join Now remain centered at rest, including long titles and optional location details. Geometry tests check symmetric widening, staged reveal/reversal, and a connected outline. A live Calendar permission prompt, user calendars, and Join handoff still require manual verification on a configured Mac.
