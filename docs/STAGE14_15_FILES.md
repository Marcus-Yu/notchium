# Stages 14–15 — Files, Transfers, Shelf, AirDrop, Screenshots

## macOS capability findings (verified)

| Need | Supported mechanism used | Limits |
| --- | --- | --- |
| Finder / download / AirDrop progress | `Progress.addSubscriber(forFileURL:)` on a folder. Other processes publish `NSProgress` for files inside it (Finder copies, Safari/Chrome downloads, AirDrop receives). Verified cross-process: main-thread callbacks, live `fractionCompleted`, finish/cancel on unpublish. File URL and operation kind come through `userInfo` (the typed accessors can be empty on a fresh proxy). | Only folders we subscribe to (Downloads). No public API for arbitrary Finder operations elsewhere. Unpublish carries no error, so it is never shown as failed. Firefox-based browsers (Zen traced) running several downloads can unpublish finished downloads below 100%; then the one read of the finished file at unpublish decides: exactly the published byte total is "Done", short or missing is "Stopped". No size polling, no fake percent: indeterminate stays indeterminate. |
| AirDrop | Retained `NSSharingService(named: .sendViaAirDrop)` and native delegate lifecycle | No public API to pick a recipient or send directly. `canPerform` false shows "AirDrop is unavailable". AirDrop returns no source window, so ShareKit presents its native centered picker rather than dimming the full transparent notch host. The existing auxiliary lease lasts through completion/cancellation, then returns to the same open page without synthesizing a hover exit. |
| Share | Owned `NSSharingServicePicker` and `NSSharingServiceDelegate` session | Picker cancellation and service completion/failure release the existing auxiliary interaction lease. The source panel lowers to the native floating level for presentation, then restores its current drag/resting level. |
| Screenshots | DispatchSource directory events plus bounded per-candidate write/attribute observation; `NSMetadataQuery` supplements other locations | No persistent polling or readiness sleeps. Off-main ImageIO validates a tiny thumbnail before emitting. Clipboard-only captures have no file and are not observable. macOS can defer the saved file while its floating thumbnail is visible; Notchium does not change that preference. |
| Thumbnails | `QLThumbnailGenerator` (downsampled, off-main), `NSCache` with a limit of 48 | Never a full-resolution decode. |
| Shelf persistence | Bookmarks (security-scoped when sandboxed), re-resolved on restore | Missing, unresolvable, or older-than-7-days items are dropped. At most 24 items. Only the reference and the date added are stored. |

## Flow

```
NSProgress / Spotlight / drops → FileTransferService / ScreenshotService / ShelfService
  → TransferActivityModel / ScreenshotActivityModel / ShelfModel (feature truth)
  → typed NotchNotification (persistent "transfer", transient "screenshot"/"shelf.added")
  → ActivityCoordinator (priority, lifetime, primary/secondary) → compact / chip / Shelf page
```

- **Active transfer:** a persistent *baseline* notification. It outranks Music, and every transient interrupts it. While anything runs there is one identity: primary transfer + "+N". When the last transfer ends, the same identity morphs into Done / Failed / Stopped for a short hold, then expires.
- **Screenshot:** transient, high priority. Rapid captures update one activity (latest thumbnail, "3 Screenshots") without replaying the entry animation.
- **Secondary indicators:** content and hit regions live inside the one animated outer shell. Music beside a transfer shows artwork; promoting Music shows a progress ring. With Calendar over Download + Music, Download occupies the left hardware flank and artwork the right. This is a projection of the existing live activities: ranking and identity stay unchanged. Calendar with only Music keeps its existing appearance. Short system transients have no indicators.
- **Drop:** the panel controller detects a file drag from the drag pasteboard's change count (only while a button is held) and, near the notch, shows a drop affordance with the feedback-banner geometry. Files are referenced, never copied. Leaving the zone retracts the affordance; nothing expands.
- **Navigation:** clicking a transfer or screenshot opens the Shelf page (explicit). Background events never change the page.

## Targeted manual-QA polish (2026-09-30)

- Shelf insertion returns the actual accepted references. Only those screenshots/completed-download representations are consumed afterward; source files are never deleted by this handoff. Missing files or bookmark failures leave their activities intact.
- Drag-out uses NSURL pasteboard writers for single/multiple files and folders. The destination owns the real operation; the source offers move/copy (copy only for read-only sources), never aliases. Option is negotiated by AppKit. Only successful copy/move completion consumes Shelf entries, preserving the existing remove-after-delivery behavior. Cancel/refusal leaves the Shelf and files untouched.
- The panel retains independent native-sharing and Finder-drag level ownership. Sharing uses the existing presentation model's named auxiliary interaction leases; neither hover exit nor picker-to-service handoff ends a live session.
- Screenshot validators coalesce incoming changes without cancelling readable results. Teardown stops the metadata query, descriptors and tasks on their owning actor.
- Native event monitors handle clicks synchronously on AppKit's main thread, before a Cancel delegate can release its lease. Share retains source-window ownership and foreground presentation; AirDrop's return policy composes with other named leases and preserves hover/pinned state.
- Minor compact system HUDs on an already-open shell use a 292 × 56 pt centered extension of the actual bottom outline. The existing compact springs and coordinator lifetimes/coalescing remain authoritative; content follows interpolated geometry and the page stays mounted without a black transition gate. Generic system HUDs (including the existing brightness fixture) reuse source-provided text; no brightness provider or polling loop is added.
- Transfer KVO snapshots are captured synchronously into a small synchronized mailbox before the main-actor hop. The first terminal outcome is immutable, and `RealFileTransferService.outcome` is the only terminal gate: completion (finished/full counts, or a complete file at unpublish) and cancellation (`isCancelled`) are the only evidence. Reset counters, teardown and the publication ending never are. Delivery remains at unpublish, bypassing the progress throttle and reading final metadata after the publisher can rename its temporary file. Publication UUIDs guard queued flushes and unpublishing callbacks, including reused Progress objects; terminal events are not dropped by a bounded stream buffer. The feature reducer rejects older timestamps and remembers terminal IDs for the monitoring session, independently of its bounded recent-file list.
- Download artwork is contained by the enlarged shell's fill/mask. Outgoing compact content yields its leading slot before restored Music artwork emerges, using interpolated shell geometry; spring timing remains unchanged.
- Home's compact Spotify Connect row uses the existing media session/device list. The previous remote ID is remembered during the session and only that ID is offered for transfer back. A missing/restricted target remains disabled. Device caching lasts 30 seconds with explicit post-transfer refresh; there is no new polling loop. Only provider snapshots confirm the active device, and transfers do not touch page selection.

Reference inspected: [BoringNotch Shelf source](https://github.com/TheBoredTeam/boring.notch/tree/main/boringNotch/components/Shelf), including bookmark entries, raw-data-only temporary storage, multi-item AppKit dragging, operation masks and terminal removal callbacks. Those interaction ideas were adapted without importing its singleton architecture or source cleanup code. Spotify transfer behavior follows the [native transfer endpoint](https://developer.spotify.com/documentation/web-api/reference/transfer-a-users-playback): omitting `play` preserves current playback state.
